# Regra do README do projeto

Parte da skill [sdd-rules](../SKILL.md).

Todo projeto deve ter `README.md` na raiz do projeto.

- Se não existir: criar ao concluir a entrega
  (ou no onboarding, se o projeto já tiver código).
- Se existir: atualizar sempre que a entrega alterar
  comportamento, comandos, configuração, dependências ou arquitetura.
  Não sobrescrever conteúdo existente; editar apenas o que mudou.

## Conteúdo mínimo

Somente com informação verificada:

- o que o projeto faz
- pré-requisitos
- como instalar, executar, testar e fazer build
  (comandos reais, os mesmos do `CLAUDE.md` do projeto)
- arquitetura de pastas (obrigatória): árvore de diretórios
  com uma linha descrevendo a responsabilidade de cada pasta relevante;
  gerada a partir da estrutura real e atualizada a cada mudança de estrutura;
  omitir dependências instaladas, saídas de build, ambientes virtuais,
  caches e artefatos gerados (ex.: `node_modules`, `dist`, `.venv`)
- como acessar o sistema em execução (URL/porta)

Não inventar conteúdo nem copiar texto genérico.

## Idioma

- Código e identificadores: inglês.
- Documentação e comunicação com usuários: português (pt-BR).
